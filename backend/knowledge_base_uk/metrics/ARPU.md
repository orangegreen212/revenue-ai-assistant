# ARPU — Середній дохід на користувача (Average Revenue Per User)

## Визначення

Average Revenue Per User (ARPU) — середня повторювана виручка на клієнта (або на активний акаунт/користувача) за період. У B2B SaaS частіше рахують на акаунт, а не на "місце"; варто уточнювати, чи йдеться про клієнта, місце (seat) чи MAU.

## Формула

```
ARPU = Загальний MRR (або повторювана виручка) / Кількість активних клієнтів
```

Варіант на місце (seat):

```
ARPU_seat = Загальний MRR / Кількість активних оплачених місць
```

Варіанти за періодом:

```
Місячний ARPU = MRR / Активні клієнти
Річний ARPU  = ARR / Активні клієнти
```

## Бізнес-інтерпретація

ARPU показує інтенсивність монетизації клієнтської бази. Зростання ARPU зазвичай походить від підвищення цін, зміни міксу тарифів, розширення (expansion) або руху в бік більших клієнтів. Падіння ARPU може сигналізувати про знижки, downsell або зсув міксу в бік дешевшого SMB-сегмента. Аналізуй ARPU разом із зростанням кількості клієнтів: виручка може зростати за рахунок більшої кількості клієнтів, вищого ARPU, або обох факторів. Для продуктово-орієнтованого (PLG) SaaS також відстежуй ARPU разом із конверсією з безкоштовного в платний тариф.

## Типові помилки

- Змішування "користувачів", "місць" та "акаунтів" у знаменнику без чіткого визначення "користувача".
- Врахування разових платежів у чисельнику, називаючи це "subscription ARPU".
- Порівняння ARPU між компаніями з різним пакуванням (per-seat vs фіксована підписка).
- Використання активних клієнтів на кінець місяця, коли виручка була зароблена іншою базою активності в середині місяця.
- Ігнорування впливу валюти та знижок при аналізі трендів ARPU.

## Поради для співбесіди

**Q:** Виручка зросла на 20%, а кількість клієнтів — на 5%. Що це означає для ARPU?

**A:** Приблизно кажучи, ARPU зросло: зростання прийшло більше з монетизації (ціна, мікс, expansion), ніж з приросту логотипів. Хороша відповідь розкладає зростання виручки на добуток зростання клієнтів × зростання ARPU (плюс ефект взаємодії), а потім перевіряє, чи ARPU зросло через expansion, ціноутворення чи зсув міксу в бік більших акаунтів.

## Приклад SQL

```sql
-- Місячний ARPU за планом
SELECT
    snapshot_date,
    plan_name,
    SUM(mrr) AS total_mrr,
    COUNT(DISTINCT customer_id) AS active_customers,
    SUM(mrr) / NULLIF(COUNT(DISTINCT customer_id), 0) AS arpu
FROM mrr_snapshots
WHERE status = 'active'
GROUP BY snapshot_date, plan_name
ORDER BY snapshot_date, plan_name;
```
