# Визначення

Monthly Recurring Revenue (MRR) — це прогнозований, нормалізований дохід, який передплатний бізнес очікує отримувати щомісяця від активних підписок. Усі інтервали білінгу (місячний, квартальний, річний) приводяться до місячного еквіваленту, щоб дохід можна було послідовно порівнювати період за періодом.

# Чому це важливо

MRR — головна top-line метрика "здоров'я" для передплатного бізнесу. Вона прибирає шум разових платежів, знижок і нерегулярних циклів білінгу, залишаючи чистий сигнал того, як розвивається повторювана база доходу. Фінанси, продажі та продукт використовують MRR як спільну точку відліку для зростання, прогнозування та звітності перед радою директорів.

# Формула

```
MRR = Σ (місячний еквівалент повторюваної плати за кожну активну підписку)
```

Нормалізація неспічних тарифів:

```
MRR з річного плану   = Річна вартість контракту / 12
MRR з квартального плану = Квартальна плата / 3
```

Міст (bridge) MRR — пояснює зміну між двома місяцями:

```
Ending MRR = Beginning MRR + New MRR + Expansion MRR
             − Contraction MRR − Churned MRR
```

| Компонент | Значення |
|---|---|
| New MRR | MRR від клієнтів, залучених за період |
| Expansion MRR | Додатковий MRR від апгрейдів, додаткових опцій чи місць |
| Contraction MRR | MRR, втрачений через даунгрейди (клієнт залишається активним) |
| Churned MRR | MRR, втрачений через повні скасування |

# Приклад

Компанія має 100 клієнтів на плані $50/місяць і 20 клієнтів на плані $600/рік.

```
MRR з місячного плану  = 100 × $50           = $5 000
MRR з річного плану    = 20 × ($600 / 12)    = $1 000
Загальний MRR                                = $6 000
```

# Типові помилки

- Включення разових платежів (сетап, послуги, обладнання) у MRR.
- Врахування повного річного інвойсу як MRR замість поділу на 12.
- Змішування визнаної (GAAP) виручки з контрактним/booked MRR без позначення, що саме звітується.
- Ігнорування пропорцій у середині місяця, коли клієнт апгрейдиться, даунгрейдиться чи скасовує підписку посеред циклу.
- Врахування призупинених, тріальних чи прострочених підписок як повністю активного MRR без чіткої задокументованої політики.

# Пов'язані метрики

- **ARR** — MRR в річному вимірі (`ARR = MRR × 12`); використовується для звітності перед радою директорів.
- **Churn Rate** — темп, з яким втрачається MRR (чи клієнти); прямий вхідний параметр MRR bridge.
- **NRR / GRR** — когортні погляди на утримання, які пояснюють, *чому* MRR змінився для конкретної групи клієнтів.
- **ARPU** — MRR, поділений на кількість активних клієнтів; показує інтенсивність монетизації на акаунт.

# Джерела

- Документація Stripe Billing (концепції підписок і білінгу, синтезовано)
- Поширені фреймворки SaaS-метрик у галузі (ChartMogul, ProfitWell, Baremetrics — синтезовано, не цитується дослівно)

*Примітка: точні бенчмарки "здорового" зростання MRR сильно варіюються залежно від стадії компанії, індустрії та go-to-market моделі — тут не наводиться жодного універсального таргету.*
