# Визначення

Annual Recurring Revenue (ARR) — це анаулізована вартість повторюваної бази доходу передплатного бізнесу. Це стандартна метрика для звітності перед радою директорів, фандрейзингу та порівняння зростання рік до року, бо вона прибирає щомісячний шум і виражає повторюваний дохід у річному масштабі.

# Чому це важливо

ARR — головна цифра, яку інвестори, ради директорів і керівництво використовують для оцінки масштабу й траєкторії компанії. Оскільки ARR виводиться напряму з MRR, його не можна вважати окремою, незалежно виміряною цифрою — будь-яка розбіжність між тим, як рахуються MRR і ARR, дасть суперечливу звітність.

# Формула

```
ARR = MRR × 12
```

Пряма анаулізація з контрактів:

```
ARR = Σ (анаулізована повторювана плата за кожну активну підписку)
```

Bridge ARR (дзеркалить MRR bridge, у річному вимірі):

```
Ending ARR = Beginning ARR + New ARR + Expansion ARR
             − Contraction ARR − Churned ARR
```

# Приклад

```
Поточний MRR = $6 000
ARR = $6 000 × 12 = $72 000
```

Для багаторічного контракту вартістю $180 000 на 3 роки:

```
Внесок в ARR = $180 000 / 3 = $60 000 на рік
```

Саме ця анаулізована цифра має потрапляти в звітність ARR — а не повні $180 000, забуковані в перший рік.

# Типові помилки

- Врахування повної вартості багаторічного контракту як ARR у перший рік замість анаулізації.
- Включення разових витрат на впровадження чи професійні послуги в ARR.
- Звітування про "booked ARR" (підписаний, але ще не активний) так, ніби він уже генерує дохід.
- Використання іншого методу округлення чи пропорцій для ARR, ніж для MRR, через що `ARR ≠ MRR × 12` у внутрішній звітності.
- Трактування зростання ARR як автоматично здорового без перевірки, чи не тримається воно на знижках чи разових промо-цінах.

# Пов'язані метрики

- **MRR** — місячна цифра, з якої виводиться ARR.
- **NRR** — показує, як ARR наявної когорти змінюється після expansion і churn, незалежно від зростання нових логотипів.
- **CAC Payback** — часто виражається відносно ARR/MRR на клієнта, щоб оцінити швидкість повернення витрат на залучення.

# Джерела

- Документація Stripe Billing (концепції повторюваного білінгу, синтезовано)
- Поширені фреймворки SaaS-метрик у галузі (синтезовано, не цитується дослівно)

*Примітка: що вважати "хорошим" зростанням ARR, сильно залежить від стадії (seed vs. growth vs. late-stage) — тут не наводиться фіксоване число.*
