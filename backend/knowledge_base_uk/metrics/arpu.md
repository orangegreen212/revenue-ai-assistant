# Визначення

Average Revenue Per User (ARPU) — іноді ARPA (Average Revenue Per Account) у B2B-контексті — це середній повторюваний дохід, згенерований на клієнта, акаунт чи активного користувача за період. Це метрика інтенсивності монетизації, а не метрика зростання.

# Чому це важливо

ARPU показує, наскільки ефективно бізнес монетизує свою клієнтську базу, незалежно від кількості клієнтів. Зростання ARPU (через зміну ціноутворення, міксу тарифів чи expansion) і зростання кількості клієнтів — два окремі важелі зростання, і їх розділення критично важливе для розуміння, *чому* змінюється виручка.

# Формула

```
ARPU = Загальний повторюваний дохід (MRR чи ARR) / Кількість активних клієнтів
```

Варіант на місце (seat) для per-seat ціноутворення:

```
ARPU (на місце) = Загальний MRR / Кількість оплачених місць
```

| Період | Формула |
|---|---|
| Місячний ARPU | MRR / Активні клієнти |
| Річний ARPU | ARR / Активні клієнти |

# Приклад

Компанія має $50 000 MRR серед 250 активних клієнтів.

```
ARPU = $50 000 / 250 = $200 на клієнта на місяць
```

# Типові помилки

- Змішування "клієнтів", "акаунтів" і "місць" у знаменнику без чіткого й послідовного визначення того, що для бізнесу означає "користувач".
- Включення разових платежів у чисельник ARPU, що завищує показник понад те, що показав би лише повторюваний дохід.
- Порівняння ARPU між компаніями з різними моделями пакування (per-seat vs. фіксована плата за акаунт), ніби вони еквівалентні.
- Використання зрізу ARPU на кінець періоду, коли клієнтська база суттєво змінилась усередині періоду, без узгодження цього руху.

# Пов'язані метрики

- **MRR / ARR** — чисельник у розрахунку ARPU.
- **LTV** — ARPU є прямим вхідним параметром у стандартній формулі LTV.
- **Customer Segmentation** — змішаний ARPU може приховувати дуже різні патерни монетизації в сегментах SMB, mid-market та enterprise.
- **CAC Payback** — ARPU (разом з валовою маржею) визначає, наскільки швидко повертаються витрати на залучення.
