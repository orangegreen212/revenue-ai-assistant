# Сегментація клієнтів — Аналітика виручки

## Визначення

Сегментація клієнтів у SaaS-аналітиці виручки — це практика розбиття клієнтської бази на змістовні групи (за розміром, планом, галуззю, когортою, регіоном, каналом залучення, health score тощо), щоб такі метрики, як MRR, churn, NRR, CAC та LTV, можна було інтерпретувати й діяти на їх основі окремо. Змішані середні часто приховують реальні драйвери зростання і ризику.

## Формула

Єдиної формули немає; сегментація застосовує стандартні метрики в межах кожного сегмента:

```
Метрика_сегмент = Метрика, порахована лише для клієнтів у сегменті S
```

Приклади:

```
NRR_enterprise = Кінцевий ARR_enterprise_когорти / Початковий ARR_enterprise_когорти
CAC_channel    = S&M_channel / Нові клієнти_channel
Churn_plan     = Втрачені клієнти_plan / Клієнти на початок_plan
```

Поширені виміри сегментації:

```
- Фірмографічні: SMB / Mid-Market / Enterprise (за кількістю співробітників чи рівнем ARR)
- Комерційні: план, інтервал білінгу, тривалість контракту
- Поведінкові: інтенсивність використання, адопція фіч, кількість тікетів підтримки
- Життєвий цикл: когорта за терміном, конверсія з трайлу vs через продажі
- Geo / галузь / канал
```

## Бізнес-інтерпретація

Сегментація перетворює "марнославні" усереднені KPI на рішення. Enterprise може мати низький logo churn, але довгий CAC payback; SMB може конвертуватися дешево, але швидко відпадати. Ціноутворення, пакування, покриття CS та маркетинговий бюджет мають відрізнятися за сегментом. Практичний операційний ритм: щомісяця переглядай MRR bridge, NRR/GRR і churn **за сегментом**, призначай відповідальних за сегменти, які дають найбільше ARR або найбільший ризик.

## Типові помилки

- Використання забагато сегментів, що перекриваються, тож у кожному "зрізі" замала вибірка.
- Сегментація лише за "марнославними" атрибутами, які не впливають на рішення.
- Зміна визначень сегментів з часом без карти міграції (ламає тренди).
- Оптимізація CAC одного сегмента на шкоду утриманню іншого.
- Звітування лише blended NRR і пропуск того, що один сегмент значно нижчий за 100%.

## Поради для співбесіди

**Q:** Які сегменти клієнтів ти проаналізував би першими для B2B SaaS revenue review?

**A:** Почни із сегментів, що пояснюють концентрацію виручки та юніт-економіку: рівень ARR (наприклад, <$5k / $5–50k / $50k+), план, канал залучення та когорта за терміном. Покажи MRR bridge та NRR/churn для кожного. Поясни, як висновки змінюють дії — наприклад, скоротити платні витрати на канал SMB з високим churn, або додати CS-ресурси для mid-market акаунтів із сильним потенціалом expansion.

## Приклад SQL

```sql
-- MRR, клієнти та ARPU за сегментом рівня ARR
WITH customer_mrr AS (
    SELECT
        customer_id,
        SUM(mrr) AS customer_mrr
    FROM mrr_snapshots
    WHERE snapshot_date = DATE '2026-06-01'
    GROUP BY customer_id
),
segmented AS (
    SELECT
        customer_id,
        customer_mrr,
        CASE
            WHEN customer_mrr < 500 THEN 'SMB'
            WHEN customer_mrr < 5000 THEN 'Mid-Market'
            ELSE 'Enterprise'
        END AS segment
    FROM customer_mrr
)
SELECT
    segment,
    COUNT(*) AS customers,
    SUM(customer_mrr) AS total_mrr,
    AVG(customer_mrr) AS arpu
FROM segmented
GROUP BY segment
ORDER BY total_mrr DESC;
```
