# Визначення

Когортний аналіз групує клієнтів за спільною початковою характеристикою — найчастіше за місяцем реєстрації — і відстежує, як поведінка саме цієї групи (утримання, виручка, expansion) змінюється з часом. Це ізолює тренди за терміном перебування, а не змішує клієнтів дуже різного "віку" в один змішаний зріз.

# Чому це важливо

Єдина цифра churn чи NRR на конкретний момент часу може вводити в оману, бо вона змішує клієнтів, які приєднались минулого місяця, з тими, хто з компанією вже три роки — а поведінка на ранньому етапі життєвого циклу зазвичай сильно відрізняється від поведінки зрілих акаунтів. Когортний аналіз — стандартний метод відповісти на питання "чи наш продукт реально стає липкішим з часом?" — на яке змішаний зріз сам по собі відповісти не може.

# Формула

Утримання когорти на місяці N:

```
Утримання когорти (Місяць N) = Клієнти з когорти, все ще активні на Місяці N / Клієнти в когорті на Місяці 0
```

Утримання виручки когорти (основа для NRR/GRR, застосованого до однієї конкретної когорти):

```
Cohort NRR (Місяць N) = ARR когорти на Місяці N / ARR когорти на Місяці 0
```

Когорти зазвичай подаються у трикутній таблиці утримання:

| Когорта | Місяць 0 | Місяць 1 | Місяць 2 | Місяць 3 |
|---|---|---|---|---|
| Січнева когорта | 100% | 92% | 88% | 85% |
| Лютнева когорта | 100% | 90% | 84% | — |
| Березнева когорта | 100% | 94% | — | — |

# Приклад

Січнева когорта реєстрацій починається із 200 клієнтів. Через три місяці 170 усе ще активні.

```
Утримання на Місяці 3 = 170 / 200 = 85%
```

Порівняння цього з утриманням березневої когорти на Місяці 1 (94% проти 92% у січня) свідчить, що недавні зміни в онбордингу чи продукті, можливо, покращують раннє утримання.

# Типові помилки

- Порівняння когорт різного розміру чи з дуже різних ринкових умов, ніби вони прямо еквівалентні.
- Погляд лише на ранні цифри найновішої когорти й оголошення успіху до того, як пройшло достатньо часу, щоб зрозуміти, чи утримання тримається.
- Змішування утримання на основі логотипів і на основі виручки в одній таблиці без позначення, яке саме наводиться.
- Ручна перебудова когортних таблиць у таблицях без послідовного, автоматизованого визначення "дати старту когорти", що спричиняє розбіжності між звітами.

# Пов'язані метрики

- **NRR / GRR** — найточніше вимірюються саме на рівні когорти, а не як єдина змішана цифра.
- **Churn Rate** — когортний аналіз показує, чи концентрується churn на ранньому терміні, чи розподілений рівномірно.
- **LTV** — когортний LTV, що дозволяє churn варіюватись за віком когорти, точніший за єдину змішану оцінку.
